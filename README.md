# xgs-26 职业培训讲师课程多权重智能匹配推演系统

## 项目简介

职业培训讲师课程多权重智能匹配推演系统，包含 Spring Boot 后端、Vue/Vite 前端、MySQL 与 Redis。

- 127.0.0.1 地址: http://127.0.0.1:8171

## 方案评审发布能力

在“智能匹配推演”基础上新增完整的方案评审发布链路（菜单：方案评审发布）：

- **带版本快照**：课程管理员可把某次推演结果保存为带版本的草稿，固化当时的课程要求、讲师关键资料（含资质/技能清单）、五项评分明细、权重配置与候选排序；之后打开永远以快照为准，不按最新资料重算。
- **双角色评审**：提交评审后候选锁定；讲师管理员核对讲师资质与可授课状态，课程管理员核对课程要求与采用权重，两类意见都通过才可发布；系统管理员可驳回但不能替代缺失的专业评审；查看者全程只读。
- **资料变更失效**：课程、入选讲师资质/可用状态、月度容量、方案权重配置在草稿创建后变化时，受影响的未发布方案自动标记失效并写明变化来源与字段明细，阻止继续评审/发布；已发布版本保留原始快照与审计事实。
- **并发唯一发布**：每门课程通过发布槽位（`published_plan_slot.course_id` 主键）+ 悲观行锁保证同时刻仅一个有效发布版本；并发双审、重复点击发布、超时重试均得到明确 409 结果，无重复评审记录/重复版本；旧版本转为 SUPERSEDED 可追溯但不得再指派。
- **正式指派原子性**：仅当前有效发布版本可发起正式指派，且固定采用快照排名第 1 的候选；指派前在讲师行锁内再次复核当前可用状态与本月容量，失败只把原因写入方案轨迹，不产生半成品、不改用排名靠后者；成功后回写来源方案、版本、候选。

接口前缀：`/api/plans`（服务端基于登录 token 强制角色，前端隐藏按钮仅为体验）。

## 讲师带教观察与改进周期

在已发生授课活动后新增完整带教改进链路（菜单：带教观察改进）：

- **分级保存与服务端可见性**：按课堂组织、内容准确性、互动引导、时间控制等维度记录事实、等级、建议，并区分 `PUBLIC`、`INSTRUCTOR_RELATED`、`RESTRICTED`。学员身份、投诉原文、内部判断和附件来源不会只靠前端遮挡；讲师仅取得本人相关且已脱敏内容，普通查看者仅见周期状态与最终结论。
- **原始记录不可静默修改**：观察保留观察人、发生时间、关联课程/场次/讲师与附件来源；事后补充只能追加。观察项原文、原等级、处理意见进入版本链，异议复核可维持、修正或撤销具体项，后续目标只依据当前 `ACTIVE` 项。
- **确认、回应与异议隔离**：讲师需确认已阅并回应；确认前可对事实提出异议。异议只能由另一名教学督导复核，原观察人不能关闭针对自己的异议；两名督导重复处理同一异议只产生一次有效状态推进。
- **阶段目标与证据链**：督导和讲师共同形成分阶段目标，明确衡量标准、截止日期、必需性和证明材料；讲师可回报进展，督导可要求补充、退回不充分证明或批准有效证据。课程负责人只有在必需目标均有有效证据后才能结案。
- **显式待处理状态**：讲师拒绝确认、逾期未回应、阶段目标逾期、督导长期未复查、升级申请、重开批准等待办均为独立状态与提醒，不合并成笼统“处理中”。
- **负责人决策与重开版本**：负责人可结案、基于写明依据延长周期或升级强化辅导。结案后发现证据错误须申请重开，负责人批准后恢复待复查；新结论必须声明替代关系，旧结论保留为历史版本不被覆盖。
- **并发与过期页面防护**：观察聚合根使用 `@Version` 乐观锁，证据与负责人决策使用客户端幂等键，时间线/提醒使用数据库唯一业务键；重复点击、网络超时重试、旧页面保存均返回冲突而不会重复推进或覆盖较新复核结果。

接口前缀：`/api/teaching-observations`。演示账号：`supervisor1`、`supervisor2`（教学督导，原观察人与复核人隔离）、`course_owner`（课程负责人）、`instructor1`、`instructor2`（讲师），密码均为 `admin123`。
